# 使用教學與問題排查

[專案首頁與安裝](../README.md) · [10 頁圖文介紹](presentation/README.md) · [資料流程](architecture.md)

這份教學從「自己的小精靈已部署、n8n 工作流已發布、Webhook 已接通」開始。尚未部署時，先完成[安裝步驟](../README.md#開始前)。作者目前沒有提供共用服務，加入作者的官方帳號不會自動取得自己的助理。

## 第一次使用：讓它收到正確群組

![群組加入與綁定](presentation/slides/03.png)

1. 在自己的 LINE Developers channel 開啟 **Allow bot to join group chats**，邀請自己的官方帳號加入目標工作群組。
2. 由擁有者私訊小精靈 `/綁定群組`。把收到的一次性指令整行貼進確定要整理的群組。
3. 依回應完成綁定與啟用。群組可用 `/工作群組 專案名稱` 命名。
4. 用 `/群組`、`/來源紀錄` 核對來源。名稱不符時先停止，不要把未知對話啟用成工作群組。

預期結果：目標來源已綁定並啟用，之後的新文字才能進入收集。加入前歷史與未加入群組的訊息無法取得。

## 傳一則測試，核對真正的摘要

在已啟用群組傳一則不含私人資訊的測試文字：

> 測試：活動文案週五下午三點交，請我確認場地。

接著私訊 `/整理`，等它送回最終摘要，核對交件資訊、可能需要確認的事，以及原文依據。

![整理前後的情境示範](presentation/slides/02.png)

「開始整理」只代表指令已受理，不代表摘要已成功送達。若沒收到結果，開啟 <http://localhost:5678>，查看對應工作流的 Executions。不要把私人訊息、執行內容或金鑰直接貼到公開 issue。

每天台北時間 21:00 已設定自動整理，電腦必須登入、保持在線且服務運行。鎖定螢幕可繼續執行，睡眠、關機或斷網會中斷，離線訊息不能保證回補。

## 沒有日期，也能整理討論內容

已啟用工作群組不只收集交件時間。可以傳這樣一段沒有日期的討論：

> 活動宣傳要用靜態圖還是短影片？靜態圖容易製作，但難說明活動內容。
>
> 我提議用短影片，可以示範互動，但需要更多拍攝與剪輯人力，大家還沒決定。

再私訊 `/整理`，核對結果是否包含：

- **聊了什麼**：比較靜態圖與短影片，保留理由與分歧。
- **已確認結論**：只有原文明確達成共識才顯示，單方面提議不算決定。
- **尚待釐清**：例如製作人力與尚未確認的選擇。
- **建議下一步**：例如先比較兩種方案的製作需求，再請群組確認。

最後一項會明確標示「AI 建議，尚未決定或執行」，不會直接建立待辦、行程或替你回覆。每個主題附同一來源的原文依據，不合併不同群組的討論。這些欄位只反映已收集的文字，仍需核對 AI 是否正確理解。

## 待回覆如何追蹤

![摘要與待回覆](presentation/slides/05.png)

私訊 `/待回覆` 查看事項。核對原文與責任人，處理後用清單中的編號傳 `/已處理 編號`。編號來自實際清單，不能直接照抄示意文字。

這裡追蹤的是小精靈資料庫中的狀態。你在其他聊天或線下完成工作，它不會自動知道，也不會代你把回覆傳給同事。

## 私訊不用先背指令

![自然語言私訊](presentation/slides/04.png)

| 可以怎麼說 | 處理方向 | 要核對什麼 |
|---|---|---|
| 週五前要交活動文案 | 辨識工作與期限 | 內容與期限是否有依據 |
| 今天有什麼行程？ | 查詢 Calendar | 日期、時間與結果 |
| 參考我的筆記，整理競賽準備重點 | 搜尋 Obsidian 片段再回答 | 筆記名稱與引用是否相關 |
| 我下週可能想開會 | 建議或追問 | 確定前不應直接建立活動 |

資訊不夠時接著補充即可，追問脈絡保留一小時。`私事` 或 `#private` 開頭能明確排除，也可用 `/暫停私訊辨識` 暫停，再用 `/恢復私訊辨識` 恢復。其餘自動分類仍可能誤判。

## Obsidian：用具體關鍵字找背景

先依[首頁設定](../README.md#obsidian-與日曆選用)填入自己的筆記庫路徑並重啟。使用筆記裡實際出現的專案名，例如「找我關於活動文案的筆記，整理交件注意事項」。

![筆記背景問答](presentation/slides/07.png)

預期結果：回答附筆記名稱與原文。找不到時換成具體關鍵字，或補充專案名稱。只讀 Markdown，最多掃描 500 篇，選最多四篇片段、每篇最多 900 字，不讀圖片與附件。

私密路徑、日記與明確私密標記會略過，未標記的私人內容仍可能被找到，選中的片段也會傳至模型供應方。

## Calendar 查詢與新增

完成自己的 Google OAuth 授權後，先問「今天有什麼行程？」或 `/行程 今天`，確認是自己的日曆與正確時間。也支援明天、本週。

![明確安排與暫定想法](presentation/slides/06.png)

「幫我排明天下午三點到四點的文案會議」是時間完整的新增要求。暫定先確認，缺日期或時間會追問。操作後核對工具結果與 Google Calendar 中的活動，不能只憑對話說「完成」就當作成功。

查詢與空閒檢查已有驗證，真實新增活動仍待補測。新增測試會實際改動日曆，請使用自己同意建立的測試活動。目前沒有修改、刪除或週期活動工具。

## 沒有反應時，照現象找原因

| 現象 | 先檢查 |
|---|---|
| LINE 完全不回應 | 電腦登入、網路、Webhook 驗證、n8n 是否發布 |
| 私訊能用，群組沒有摘要 | 同一個 bot 是否已入群、來源是否綁定並啟用、是否為啟用後的新文字 |
| 說開始整理，卻沒送摘要 | n8n Executions 是否失敗、模型是否限流、原文是否進入收集 |
| 顯示沒有待回覆 | 是否完成摘要、原文是否有處理要求、是否已完成或超過保留期限 |
| 問筆記卻找不到 | 路徑、Markdown 格式、關鍵字及私密排除規則 |
| 日曆無法查詢 | Google 授權是否完成、是否仍有效 |
| 重開機後不能用 | 是否登入 Windows、監控工作是否啟用、網路是否恢復 |

本機入口：n8n <http://localhost:5678>、資料服務 <http://127.0.0.1:8787/health>、relay <http://127.0.0.1:8790/health>。健康檢查成功只證明該服務有回應，不代表模型、LINE 推播與 Google 授權都成功。

## 暫停、停止與資料

群組 `/暫停收集` 暫停，`/停止收集` 停止並清除該來源的本機資料。備份有自己的保留週期，停止不等於既有備份與外部供應方紀錄立即消失。

SQLite 與 OAuth 檔案沒有額外應用層加密。原訊息、事件與摘要快照保留七天，待辦三十天，每日備份保留七天。完整限制見[資料與隱私](../README.md#資料隱私與限制)。
